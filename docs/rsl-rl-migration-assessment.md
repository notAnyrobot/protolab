## Recommendation

The latest published release checked on this date is **5.5.1**: GitHub's latest-release endpoint resolves to [v5.5.1](https://github.com/leggedrobotics/rsl_rl/releases/tag/v5.5.1), also published on [PyPI](https://pypi.org/project/rsl-rl-lib/5.5.1/). The local RSL-RL checkout matches that tag.

Keep ProtoMotions as the main learning framework for motion imitation, skill learning, and pretrained motion-policy adaptation. An **optional RSL-RL backend for plain PPO experiments** is a reasonable bounded experiment if ProtoLab needs its model choices, symmetry/RND support, or interoperability with other RSL-RL projects. **Replacing the entire `protomotions/agents` tree is not justified by the 5.5.1 fixes alone.** Several existing capabilities would become custom RSL-RL algorithms and models that ProtoLab would have to maintain.

RSL-RL is extensible; missing built-in features do not mean they are impossible. The cost is implementing and validating them while retaining their specialized state, data, and loss contracts. Both implementations already support distributed training; no measured evidence here establishes that RSL-RL trains this workload faster or learns a better policy.

| Decision | Relative effort | Assessment |
|---|---|---|
| Keep current default | Low | Best fit for the existing motion-learning stack |
| Add optional plain-PPO backend | Medium | Worth a bounded pilot if RSL-specific features are needed; requires environment adapter and semantic tests |
| Replace PPO underneath existing motion workflows | High | Must preserve subclass hooks, specialized objectives, storage and checkpoint contracts |
| Replace all agents | Very high | Requires AMP/ASE, latent imitation and PEFT ports; no demonstrated return yet |

## PPO is mathematically related, but not behaviorally identical

Both implement GAE, a clipped policy surrogate, optional clipped value loss and entropy regularization. Reusing hyperparameter names alone would not preserve a run:

- **Separate versus joint optimization.** ProtoMotions constructs independent actor and critic optimizers and steps them separately; its default optimizer learning rates are `2e-5` and `1e-4`. RSL-RL's standard PPO constructs one optimizer, and combines policy/value/entropy objectives. The learning-rate schedule and weighting must be chosen deliberately. [ProtoMotions setup](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/ppo/agent.py:126), [defaults](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/ppo/config.py:75), [RSL setup](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/algorithms/ppo.py:99), [RSL loss/update](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/algorithms/ppo.py:270).
- **Normalization.** ProtoMotions advantage normalization can use an EMA, minimum standard deviation and clamping; it also supports reward normalization with corresponding value conversions. RSL-RL offers rollout-wide or minibatch advantage normalization and updates actor/critic observation normalizers after optimization. A comparison must align these choices rather than inherit both defaults. [ProtoMotions settings](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/ppo/config.py:86), [reward/value conversions](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/ppo/agent.py:326), [RSL returns](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/algorithms/ppo.py:166), [RSL normalizer timing](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/algorithms/ppo.py:327).
- **Bootstrap semantics.** ProtoMotions evaluates the next observation's critic value per transition, zeroing it for true termination. RSL-RL uses its runner/VecEnv timeout convention. An adapter must preserve final observations and separate timeout from true termination; simply discarding ProtoMotions' `terminated` output is incorrect. [ProtoMotions next value](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/ppo/agent.py:304), [RSL timeout handling](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/algorithms/ppo.py:137).
- **Policy likelihood semantics.** Standard ProtoMotions PPO samples a Gaussian and records negative log probability; its specialized PEFT RLFT instead replays sampled prior tokens and computes categorical PPO ratios. RSL-RL's built-in continuous distributions do not substitute for that token-space objective. [Gaussian actor](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/ppo/model.py:43), [token PPO](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/peft/prior_agent.py:100).

## Checkpoints and migration boundaries

The environment adapter must manage resets, not just reshape return values. ProtoMotions' loop explicitly calls `env.reset(done_indices)` before collecting the next action, and `BaseEnv.step()` returns five values including separate `dones` and `terminated`. RSL-RL expects a four-value step result and does not perform these environment resets in its runner. Its timeout reward correction uses the stored current-state value; ProtoMotions explicitly evaluates the next-state value before reset. Mapping `time_outs = dones & ~terminated` alone therefore does not establish identical bootstrap targets. Test both true terminations and time-limit truncations, and deliberately choose whether to adopt RSL-RL's default targets or preserve ProtoMotions' semantics. [ProtoMotions rollout](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/base_agent/agent.py:715), [environment step](/home/android/workspace/protolab/external/ProtoMotions/protomotions/envs/base_env/env.py:687), [RSL VecEnv contract](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/env/vec_env.py:47), [RSL timeout correction](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/algorithms/ppo.py:154).

Motion evaluation can change training itself: `MimicEvaluator` updates motion-sampling weights from evaluation failures, and the base agent can switch motion shards after evaluation. Retaining these behaviors requires integrating evaluation and motion state with the new runner; ordinary reward logging is insufficient. [Sampling updates](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/evaluators/mimic_evaluator.py:100), [motion-shard transitions](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/base_agent/motion_shards.py:34).

Existing checkpoints are not directly interchangeable. ProtoMotions saves a combined model, separate PPO optimizers, training progress, normalization/evaluator state and motion-shard state, with environment snapshots alongside training checkpoints. RSL-RL PPO saves separate actor/critic state dictionaries and a joint optimizer state. An inference-weight converter could be written for a specifically matched architecture and normalization scheme, but this would not make optimizer state or full training resume equivalent. PEFT checkpoints additionally preserve frozen-prior/reference contracts. [ProtoMotions base state](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/base_agent/agent.py:378), [PPO state](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/ppo/agent.py:248), [environment save](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/base_agent/agent.py:450), [RSL save/load](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/algorithms/ppo.py:374), [PEFT reference resume](/home/android/workspace/protolab/external/ProtoMotions/protomotions/agents/peft/prior_agent.py:42).

For a pilot, retain ProtoMotions environments, simulation and motion infrastructure, expose an explicit experiment backend choice, and implement a ProtoLab-owned VecEnv adapter and RSL runner/config entry point. Start new plain-PPO runs using a small G1 MLP tracking task with a supported simulator. Verify observation groups, action scaling, reset timing, rewards and bootstrap targets before spending compute on learning curves. Compare equal environment steps, seeds, architecture, normalization and evaluation tasks; record learning quality, throughput, GPU memory and resume behavior. Expand only if the measured gain justifies the extra backend maintenance. Defer AMP/ASE/MaskedMimic/PEFT migration until there is a concrete capability or maintenance benefit that outweighs rebuilding those pipelines.

Changing the agent `_target_` alone is insufficient: RSL-RL PPO has a different constructor and lifecycle. A separate launcher should reuse environment/config construction while owning its own runner. Multi-GPU execution also needs one distributed lifecycle owner: ProtoMotions launches Fabric, while RSL-RL's runner initializes its own process group. Composing those unmodified launchers would need careful reconciliation. [ProtoMotions launch](/home/android/workspace/protolab/external/ProtoMotions/protomotions/train_agent.py:803), [RSL distributed setup](/home/android/workspace/github/mujocolab/rsl_rl/rsl_rl/runners/on_policy_runner.py:208).
